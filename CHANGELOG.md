# Changelog

All notable user-visible changes to this project are documented in this file.

## Unreleased

- **New:** Tours. An event can be planned as a tour ("Als Tour planen" in the event's "…" menu); its location becomes stop 1. The tour page lists stops (location, setup, event and teardown times, contact on site, note) and waypoints between them (warehouse, company address, a saved or a custom address; purpose loading, overnight stay, break or other; optional times) in driving order; the event's dates follow its stops. The planned articles of the event are the base list for every stop; per stop the material can deviate, also as a bulk action for several stops ("nur dieser", "dieser und alle folgenden", "alle nicht begonnenen", "alle"). Additional material either travels the whole tour or is only occupied around the affected stops, optionally loaded/unloaded at a warehouse waypoint; availability warnings and the issue checklist take it into account. The crew can deviate per stop as well (replacement, additional technician, not there): replacements are requested as usual, and whoever is no longer needed gets an e-mail. Each stop can get its own minute program. Load lists per stop (needed material plus what to load/unload compared to the previous stop) can be viewed, printed or downloaded as PDF. Tours are marked with 🚚 in the event list (with expandable stops) and in the calendar, where the stops of the day are shown below the tour. A recurring event can copy a tour with all its stops. Requires migration 177.
- **New:** Recurring events. Any event can be turned into a series ("Wiederkehrend machen" in the event's "…" menu): choose a rhythm (every n weeks on chosen weekdays, monthly on a day or on the n-th weekday, yearly, or a free list of dates) and an end (date or number of occurrences, at most 100 / 2 years at once). A preview table lists the proposed dates with warnings for company holidays, exclusive events and material that is already planned elsewhere; each date can be moved, given another location or left out. The occurrences are ordinary events that take over the selected areas from the original event: planned material (articles, bundles, sets), location, logistics (relative to the new date), technicians and trades (requested again), minute programs (times moved along) and power planning. On an occurrence, "Aus vorherigem Termin übernehmen" and "Auf folgende Termine übertragen" replace chosen areas after a before/after preview; occurrences whose material has already been issued are never changed. The series page shows all occurrences with material warnings and lets you generate further occurrences, change the rhythm from a date on (free occurrences move with their data, started or manually moved ones stay), or end the series. Occurrences are marked with 🔁 in the event list and the calendar. Requires migration 176.
- **New:** REST API v1 covers the main areas of the web interface. Besides articles, tokens can now read and partly write customers, master data (suppliers, venues, warehouses, vehicles, categories, manufacturers, sets, labor time articles), events with their items, offers and order confirmations, invoice drafts (finalizing and cancelling need their own scope), receipts and purchase orders, and can read invoice corrections, dunning notices, bank accounts, cases, racks, RMAs, electrical inspections, sales, minute programs and reports. PDFs and XRechnung can be downloaded, documents e-mailed, and shops can query article availability for a period. Each token gets scopes per area (read/write) plus an optional "read only" switch and its own request limit; existing tokens keep their previous access (read articles only). Requests are limited per token and minute (default 600, counted in the database or in Redis via Unix socket, TCP or TLS, with automatic fallback to the database), and every write request is logged under Settings > API for 90 days. The documentation (`api-docs.html`, built from `docs/openapi/`) describes every endpoint. Requires migration 175.
- **New:** Skipping confirmations with Shift everywhere, and configurable. Holding Shift while clicking (or pressing Shift+Enter on the focused button) now skips every confirmation, including those in the minute program pages, the FOH live screen, the display client and the event audio live view; while Shift is held, the affected buttons are outlined, and the confirmation dialog shows a tip. Administrators switch the shortcut on or off under Settings > Security and choose there which confirmations can never be skipped (by default: security actions such as deleting users, API tokens and passkeys, and sending, cancelling or deleting invoices and invoice corrections). Each user can switch it off for themselves under Profile > Display. When an event or customer is deleted and its storage folder is kept, a notice now says so. Requires migration 174.
- **New:** AI ad images can be added to the regular product gallery of an article ("In Galerie" below each ad image); a copy is appended to the gallery, the ad image stays.
- **New:** Option "Preis ins Bild einfügen" when generating AI ad images renders the daily rental price into the image. The price is no longer part of "Weitere Eigenschaften".
- **New:** Option "Galeriebilder als Vorlage verwenden" (on by default when the article has photos) sends up to four gallery photos to the AI so the article is depicted correctly; with several photos a single photo can still be chosen instead.
- **Fixed:** Generating AI ad images now shows the large loading spinner (with elapsed time) like refining does, and it stays visible for as long as the generation may take instead of disappearing after 30 seconds.
- **Fixed:** The start page no longer crashes when the tiles "Offene Bestellungen", "Offene Angebote" or "Offene Auftragsbestätigungen" contain at least one entry (for example a purchase order with status "Bestellt").
- **New:** Technician page for planners. Users with "Ausgabe und Rücknahme" now find technicians in the global search; a hit opens a read-only page `/techniker/{id}` with e-mail, phone and upcoming assignments (administrators get a link to the user form). Technician names in the technician section of an event link to this page.
- **Fixed:** The header no longer overflows for administrators with every menu item between 1024 and about 1280 px window width. Below 1536 px the user menu shows an icon instead of the name (the name stays at the top of the menu), and between 1024 and 1280 px the menu items are spaced more tightly.

- **New:** Average power for articles. In addition to the peak power (formerly "Eingangsleistung"), an article can now have an average power in watts. If an average is recorded, only it is shown on the article and used in the power planning of events (marked "Ø"); otherwise the peak power is used as before.
- **New:** Large loading spinner in the centre of the page. Whenever opening a page or submitting a form takes noticeably long (more than about 0.4 s), a big spinner with "Wird geladen …" now covers the page until the next page appears, in addition to the thin bar at the top. It also shows on the login pages, can be dismissed with a click or Escape, and is skipped for file downloads.
- **Fixed:** Drop-down panels such as the "Dokumente" menu of an event no longer stick out past the right edge of the screen on small devices; they are moved back into the visible area.
- **New:** Global search. Ctrl+K (⌘K on a Mac) or the new search button in the header opens a search field in the middle of the screen that finds events, articles (also by inventory number), customers, suppliers, technicians, venues, purchase orders, receipts and — by their number — offers, order confirmations, invoices and invoice corrections. Suggestions are grouped by type with a matching icon and can be opened with the arrow keys and Enter. Each user only finds what their permissions allow; users who are technicians only find the events they work on.
- **New:** Messages from FOH to the stage. The FOH live screen of a minute program has a new "Nachricht an die Bühne" card (with text suggestions, an urgent flag and optionally all minute programs of the event); the message appears on the stage display until FOH withdraws it. Share links with edit rights can send too. The run sheet API v1 marks these messages with `fromFoh`. (#49)
- **New:** Login via LDAP / Active Directory or OAuth 2.0 / OpenID Connect. Administrators choose exactly one login method (local, LDAP or OAuth) under Settings > Login (LDAP/OAuth); external identities are matched to local users by e-mail address, with optional automatic creation of unknown users using default permissions. Administrators keep the local login at `/login/lokal` as emergency access. (#47)
- **New:** Per-trade notes in minute programs. Each program item now has one note per trade in addition to the general note, replacing the fixed sound/light/video/stage columns; the trades of a program are chosen in the program form or derived automatically from the event and its technicians. The FOH live screen shows every note as a colour-coded card per trade with filter chips, and the run sheet API v1 gains `trades` and `tradeNotes` (the legacy `notes` keys are still filled). Existing notes are migrated to the trades "Ton", "Licht", "Video" and "Bühne". (#48)
